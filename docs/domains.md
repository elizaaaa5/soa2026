# Домены маркетплейса

## Обзор

Система маркетплейса разделена на 6 доменов на основе Domain-Driven Design (DDD) принципов. Каждый домен имеет четкую зону ответственности и владеет своими данными.

## Список доменов

### 1. User Management

Зона ответственности:
- Регистрация новых пользователей (покупатели и продавцы)
- Аутентификация и авторизация
- Управление профилями пользователей
- Управление ролями и правами доступа

Основные сущности:
- User - пользователь (ID, email, пароль, роль)
- Profile - профиль (имя, адрес, телефон)
- Role - роль (BUYER, SELLER, ADMIN)
- Session - сессия пользователя

Бизнес-инварианты:
- Email уникален в системе
- Пароль хешируется перед сохранением
- Только продавец может добавлять товары

---

### 2. Product Catalog

Зона ответственности:
- Управление товарами и категориями
- Поиск и фильтрация товаров
- Управление инвентарем (количество на складе)
- Управление ценами и скидками

Основные сущности:
- Product - товар (ID, название, описание, цена, seller_id)
- Category - категория (дерево категорий)
- Inventory - инвентарь (product_id, quantity, reserved_quantity)
- Price - цена (product_id, amount, currency, valid_from)

Бизнес-инварианты:
- Цена всегда положительна
- Количество товара >= 0
- Seller может редактировать только свои товары

---

### 3. Order Management

Зона ответственности:
- Жизненный цикл заказа
- Управление корзиной
- Изменение статусов заказа
- История заказов

Основные сущности:
- Order - заказ (ID, user_id, status, total_amount, created_at)
- OrderItem - позиция заказа (order_id, product_id, quantity, price)
- Cart - корзина (user_id, items)
- OrderStatus - статус (CREATED, CONFIRMED, SHIPPED, DELIVERED, CANCELLED)

Бизнес-инварианты:
- Общая сумма заказа = сумма всех позиций
- Статусы переходят только в определенном порядке
- Отмененный заказ нельзя изменить

---

### 4. Payment Processing

Зона ответственности:
- Инициация платежей
- Валидация платежных данных
- Обработка результатов платежей
- Управление транзакциями

Основные сущности:
- Payment - платеж (ID, order_id, amount, status, method)
- Transaction - транзакция (payment_id, gateway_transaction_id, response)
- Invoice - счет (ID, order_id, amount, issued_at)
- PaymentMethod - способ оплаты (CARD, WALLET, CASH)

Бизнес-инварианты:
- Сумма платежа = сумме заказа
- Платеж нельзя инициировать дважды
- Успешный платеж нельзя отменить (только refund)

---

### 5. Notifications

Зона ответственности:
- Отправка уведомлений пользователям
- Управление каналами доставки (email, push, SMS)
- Управление шаблонами уведомлений
- История отправленных уведомлений

Основные сущности:
- Notification - уведомление (ID, user_id, type, channel, status)
- Template - шаблон (ID, event_type, subject, body)
- DeliveryLog - лог доставки (notification_id, timestamp, status)
- Channel - канал (EMAIL, PUSH, SMS, TELEGRAM)

Бизнес-инварианты:
- Уведомление имеет уникальный ID
- Неотправленное уведомление можно переотправить
- Шаблон нельзя изменить если он активен

---

### 6. Personalization

Зона ответственности:
- Формирование персонализированной ленты товаров
- Рекомендации на основе поведения пользователя
- Аналитика взаимодействия с товарами
- Управление очередью рекомендаций

Основные сущности:
- UserBehavior - поведение (user_id, product_id, action, timestamp)
- Recommendation - рекомендация (user_id, product_id, score)
- FeedItem - элемент ленты (user_id, product_id, position, generated_at)
- ActionType - тип действия (VIEW, ADD_TO_CART, PURCHASE, LIKE)

Бизнес-инварианты:
- Рекомендации уникальны для пользователя (no duplicates)
- Score в диапазоне [0, 1] (вероятность покупки)
- Лента формируется на основе действий за последние 30 дней

---

## Карта доменов

Архитектура доменов:
- Users - Управление пользователями
- Catalog - Товары
- Orders - Заказы
- Personalization - Рекомендации
- Payments - Обработка платежей
- Notifications - Отправка уведомлений

Связи между доменами:
- Users связан с Catalog, Orders, Personalization
- Orders связан с Catalog и Payments
- Payments связан с Notifications

## Bounded Contexts

- Identity Context: User Management (Регистрация, вход, восстановление доступа)
- Catalog Context: Product Catalog (Создание товара, поиск, просмотр)
- Order Context: Order Management + Payment Processing (Корзина, оформление заказа, оплата)
- Communication Context: Notifications + Personalization (Отправка уведомлений, рекомендации)

---

## Заключение

Четкое разделение на домены позволяет:
- Изолировать ответственность команд разработки
- Независимо масштабировать части системы
- Минимизировать связность между сервисами
- Упростить тестирование и отладку
